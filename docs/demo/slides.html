Why it looks like this

one person, coding agents in parallel, about a week from diagram to v1.0
Keep the live path light Audio streams into Muse Voice as it is spoken: one session for your mic, one for the call. Only finished turns go to Spark, and turns that pile up are folded into the next call. Pushing the live stream straight through Spark could not keep up. So the recording is a third stream written straight to disk, and the notes are built from stored events after the call.
Contracts before code Every arrow on the diagram is a JSON Schema. Python and TypeScript types are generated from them, and every model reply is schema-checked. Everything depends on them, so one agent wrote them first and nobody else coded until they were done.
One folder per module, one agent per lane Each module is a lane in its own git worktree. Lanes ask each other through GitHub issues; a linter fails CI if one module imports another. That is what let three agents build at the same time without breaking each other.
One process, one event bus A modular monolith: modules talk only through an in-process bus. No Redis, no LangGraph, no Pipecat. It runs on one laptop and starts with one command, so the moving parts stay few.
Local, nothing hosted Open source, no logins, no cloud backend. Notes, transcripts and recordings stay on your PC; API keys live only in the backend. The extension holds no keys and talks only to 127.0.0.1, behind pairing and origin checks.
Reliability only where it is needed Acks and resends only on the browser-to-backend socket, the one place a message can get lost. Inside the process a publish returns at once. Choosing that saved about 8-10 agent-hours of plumbing.
Test without a live call A fake Meet page, fake speech and fake models, and a replayer for recorded calls, built alongside the first modules. The full chain, audio to bubble, had to pass on the rig before going live.
Measure first Day-0 probes before any module: Spark's median was 2.7 s on a live-points prompt, against a ~3 s target from pause to point. The probes fixed the fallbacks up front: a slow model fails over; weak Arabic speech would mean an English-leaning demo.

Set it up and run it

Windows, macOS or Linux
  1. You need Google Chrome, Git, Node.js 22+, a headset and a Meta Model API key. Setup installs uv, which brings Python 3.12.
  2. Get it and run setup
    git clone https://github.com/xKarimAm/halo.git then cd halo
    powershell -ExecutionPolicy Bypass -File .\setup.ps1 (macOS/Linux: sh setup.sh). It asks for your key (kept only in the git-ignored .env), builds the extension and starts the backend.
  3. Load the extension chrome://extensions → Developer mode → Load unpacked → extension\.output\chrome-mv3. Click the Halo icon: it pairs by itself and says Connected.
  4. Try it without a call uv run python packaging/demo.py plays three scripted meetings (English, Arabic, mixed) in about 3 minutes; then open http://127.0.0.1:8765. Later starts: uv run halo.
  5. Live Join a Google Meet with a headset, open the Halo popup, press Start. Points float on the tiles; the notes are waiting when the call ends.
  6. Optional in .env: BASETEN_API_KEY (Muse Spark Open first), HALO_GEMINI=search,backup + GEMINI_API_KEY. No key? uv run pytest backend contracts -q and npm --prefix extension test still run.
